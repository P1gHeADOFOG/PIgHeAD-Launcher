3. Locally stored data
The PHL folder beside the launcher EXE stores the game directory library, launcher settings, agreement revision and content hash, consent time, encrypted authentication caches and imported modpack data. Each game's PHL folder stores its settings and game logs. For .minecraft directories, PHL is created beside .minecraft in the parent folder. The runtime creates a .net cache in the user's temporary directory. Game files, dependencies and instance data remain in your selected game directory. Previous versions' user-directory data is not automatically deleted; old authentication tokens are not automatically copied. Consent records only determine when renewed consent is needed and do not prove third-party authorization.

4. Credential security
Microsoft token caches are encrypted with Windows DPAPI for the current user. Xbox and Minecraft tokens are used only in memory and are not written to settings JSON. The launcher does not record complete launch commands and masks the current Minecraft token in game logs. Software running as the same Windows user that inspects process arguments may still read tokens passed to Java. Protect your device and system account.

5. Telemetry, logs and deletion
This version has no launcher telemetry or automatic log uploads. Games, loaders, mods and external installers may have separate data practices; review their notices. Game logs may include player names, local paths and server addresses. Review and redact logs before sharing. Sign out in Accounts to clear this launcher's authentication cache. Close the launcher and back up anything you need before deleting local data. Deleting consent records requires renewed consent at the next launch.
